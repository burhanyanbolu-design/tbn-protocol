ICV Lab — Independent Claim Verification free tool

Structural verification for computational research claims. Runs entirely in your browser — nothing is uploaded.

Most computational claims are published with the author's own measurement and no independent check against alternatives. The number is usually correct. The problem is that nobody asked whether a deliberately wrong version would have scored just as well.

If this claim were wrong, would this experiment have caught it?

That is the only question this tool answers. It re-measures a submitted claim from the raw structure, builds a population of matched control variants, and reports where the real one ranks among them. A claim that cannot beat its own controls has not been demonstrated, regardless of how carefully it was measured.

1Independent measurement

We recompute the claimed value from the submitted structure. The claimant's own number is never trusted, only checked. Getting this right is necessary and not sufficient.

2Matched controls

Variants are built by degree-preserving double-edge swaps, so every control has the identical degree sequence as the submission. Not a straw man — a fair rival.

3Ranking

The real structure is ranked against the controls on the claimant's own declared metric, with ties counted separately. Rank is the result; the raw value is not.

4Declared pass rule

The claimant states their own success threshold before testing. We do not invent the bar, and we do not move it afterwards.

Submission

The claimant declares their own metric and pass rule. We measure it independently and rank it against matched controls with identical degrees.

What this does and does not do

  

    

      
It does

      
    
        
  • Re-measure a claim independently from the submitted structure.
    • 
        
  • Build matched controls with an identical degree sequence.
    • 
        
  • Report the claim's rank and percentile among those controls.
    • 
        
  • Fingerprint the exact bytes submitted, with SHA-256.
    • 
        
  • Fail closed. Malformed or unmeasurable input returns
            NOT TESTABLE with a specific reason, never a guess.
    • 
        
  • Give a reproducible result. The control generator is seeded, so the
            same submission yields the same verdict.
    • 
      

    

    

      
It does not

      
    
        
  • Simulate anyone's algorithm, physics, or runtime behaviour.
    • 
        
  • Verify quantum advantage, speedup, or hardware performance.
    • 
        
  • Audit source code, security, or correctness of an implementation.
    • 
        
  • Issue a certification, accreditation, or endorsement of any kind.
    • 
        
  • Prove a claim true. A SUPPORTED verdict means the experiment
            could have caught the error and did not, which is weaker than proof.
    • 
        
  • Replace peer review or domain expertise.
    • 
      

    

  


  
Verdicts

  
    
    
  • SUPPORTED — the claimed value reproduced, and the structure met the
        claimant's declared rank threshold against matched controls.
    • 
    
  • FALSIFIED — the declared threshold was not met. Note this can happen
        even when the claimed number is perfectly correct, which is the most common
        and most useful outcome.
    • 
    
  • INCONCLUSIVE — the test could run but the pass rule was unsupported
        or indeterminate.
    • 
    
  • NOT TESTABLE — the submission could not be measured as supplied.
    • 
  


  
Supported metrics

  

    
endpoint_distanceShortest path in hops between two declared nodes.
      Objective is normally minimise.

    
quotient_cellsCell count of the coarsest exact equitable partition,
      seeded from the two endpoints. Detects whether a structure admits a genuine
      quotient or refines to discrete. Objective is normally
      minimise.

  

  
Anything else returns NOT TESTABLE. Additional metrics can be
  added on request; each needs its own adapter and an agreed definition before use.


  
Submission format

  

  
controls defaults to 200. Node identifiers may be any JSON value
  that compares equal consistently; integers are recommended. Self-loops and malformed edges
  are rejected at intake.


  
Why matched controls, specifically

  
Comparing a structure against a random graph proves very little, because a random graph
  usually differs in degree distribution and therefore in trivial ways. Degree-preserving
  double-edge swaps hold every node's degree fixed while rewiring who connects to whom. What
  remains is the thing actually being claimed: the arrangement. If the arrangement
  matters, it will beat its own rewirings. If it does not, it will not.


  
Our own claim, tested by this tool

  
We built this after applying the same process to our own research. Our Elastic Overlapping
  Grid structure was measured correctly at a corner-to-corner distance of 6, and it still ranked
  195th of 201 against matched controls, because most rewirings did better. We closed that
  research line as a result. The Load our self-audit button above reproduces that verdict
  in your browser, and you are welcome to check it.

  
A verification service that has never returned a negative — including against its own
  author — is not evidence of anything. This is ours, on the record.


  
Privacy

  
All computation happens locally in your browser using JavaScript embedded in this page.
  Submissions are not transmitted, stored, or logged by us, and the page makes no network
  requests after loading. You may save this file and run it fully offline. If you are handling
  unpublished work, verify this yourself with your browser's developer tools before use.
